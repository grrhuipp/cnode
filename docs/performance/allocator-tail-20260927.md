# 全局分配锁尖峰：定位与回归结果

## 范围

- 基线：线上版本 `f616af1`。
- 已验证候选：`73772e6`，静态 musl SHA256：`61b588f4a1cd6ad9c305027d0a5806c7e3ad7359f82d0d3846e718ce8c01fc18`。
- 只修改应用代码和测试；本轮 Asio 库补丁实验已撤回，原有依赖补丁不变。
- 没有替换、重启线上服务；以下性能数据来自同机隔离实例，不是上线收益。

## 根因证据

原始线上 CPU 记录共 16616 个样本，无丢失。尖峰区间为单调时钟 26016.6–26023.8 秒，futex 地址 `0xe1aa60` 对应该构建的 `__malloc_lock`。

musl 缺少可用展开信息。使用匹配的 ELF/符号和实际指令，离线还原 `__lock → malloc → OpenSSL` 的固定栈调整；没有扫描栈猜测返回地址，也没有重新探测线上 malloc。

选中的 334 个锁等待样本中，240 个为 malloc 路径，94 个为 free/wrlock 路径。240 个 malloc 样本中：

- 228 个经过 OpenSSL 分配；
- 106 个直接来自 `ss::AesBlockCrypt`，89 个经 EVP 初始化回到该函数；
- 只有 3 个经 `aligned_alloc`。

因此，主要修复点是 Shadowsocks 每块 AES 和每包 AEAD 的临时 EVP 堆对象，而不是扩大 Asio 缓存。

前期 AnyTLS 分配探针实验的约 82% 分配次数下降，**不能视为线上 CPU 修复证据**。未加分配探针的快速下载/背压下载未复现同样的 malloc 锁热点。

## 实现边界

- `AesBlockCrypt` 使用 AWS-LC 现有公开 AES API，在当前同步操作的栈上生成密钥调度，操作结束后清除；保留硬件/软件派发和 AES-128/256 限制。
- 原生 UDP 的单次 AEAD 使用公开 `EVP_AEAD_CTX_init/seal/open/cleanup`，上下文仅存活于当前同步操作，结束后清除。
- 流式加解密会话、Worker 所有权、用户快照、路由、调度器和 TLS 缓冲容量没有改变。
- 没有新增连接常驻字段、缓存池、全局分配替换或跨 Worker 状态。
- 同时减少了应用层无竞争写入门、无填充转调、TLS 写入等待和 AnyTLS 编码发送的中间协程。编码视图仅借用当前写入阶段的 payload。

## 性能验证

固定条件：4 个 Worker、128 个用户、32 个 UDP 客户端，认证最后一个用户，64 字节 payload，客户端间隔 10 ms，测量 20 秒、随后空闲 22 秒。每个客户端使用独立 loopback 目标；Python 独立加解密并核对会话、时间戳和 payload。显式关闭与该加密测试无关的嗅探。

每种配置执行三组交替顺序的基线/候选对照，不启用分配探针。下表各项分别取三次中位数；CPU 100% 表示占用一个核。

| 指标 | 有身份密钥：基线 → 候选 | 无身份密钥：基线 → 候选 |
| --- | --- | --- |
| 进程 CPU 时间 | 51.00 → 9.02 秒 | 50.84 → 16.84 秒 |
| 系统 CPU 时间 | 27.32 → 2.78 秒 | 26.60 → 2.74 秒 |
| CPU P99 | 288.30% → 49.91% | 304.09% → 89.79% |
| 请求 RTT P99 | 25.17 → 2.85 ms | 48.34 → 3.25 ms |
| 完成吞吐 | 2272 → 3003 包/秒 | 1771 → 3005 包/秒 |
| 每完成包 CPU | 1230.95 → 150.26 µs | 1434.50 → 280.23 µs |

使用相同 CI 管线、已包含协程修改但未包含加密修复的 `16aeb40` 做附加对照，仍有 53.65/49.79 秒 CPU 和 22.42/54.28 ms RTT P99。这支持收益主要来自加密修复，而非 CI 管线或协程调整。

另做 49 Hz、有界、无丢失的 CPU 采样：

- 身份密钥基线 2608 个样本：malloc 实现 9.82%、`__lock` 7.78%、内核 queued-spin 慢路径 6.40%，futex 等待/唤醒明显。
- 候选身份密钥/无身份密钥分别 435/809 个样本，未采到 `__lock`、futex 等待/唤醒或 queued-spin 慢路径；热点转为正常的 BLAKE3/AES 运算。
- 有限采样不意味着进程绝对没有其他 malloc 或锁；修复消除的是已确认的主要来源。

## 空闲内存与正确性

两轮 256/1024 条空闲 TLS 连接的对照，所有连接均成功恢复心跳：

- 从连接数增量估计的常驻成本：基线约 **22.58 KiB/连接**，候选约 **22.54 KiB/连接**，未见随连接数增长的额外内存。
- 整个进程 RSS 有约 **0.1–0.2 MiB 的固定差额**，不能表述为总 RSS 完全不变。
- 512 连接传输 4 GiB 后，双方均出现传输后内存回落，且全部恢复心跳；候选空闲 CPU 约 1.22%，基线约 1.18%。

回归覆盖 AES-128/256 标准向量、原地及非对齐输入输出、输出边界、非法密钥长度、Linux 分配计数、禁用硬件能力的 AES 测试、AEAD 与原流式 EVP 的密文/tag 一致性、篡改 tag 拒绝、SS2022 AES-256、重放窗口及既有协议/取消/背压测试。

[CI 36299625061](https://github.com/grrhuipp/cnode/actions/runs/36299625061)：musl **141/141**、glibc **143/143**（含既有 ASan/UBSan），无编译警告或弃用警告。Windows **141/141**；另以 `OPENSSL_ia32cap=0` 运行 UDP 加密回归通过。

## 限制与证据位置

- 原基线在多个客户端共用同一 UDP 目标时出现回包身份交叉；该既有问题未在本轮修改，不能声称已验证该场景。性能对照使用独立目标。
- 尚未部署，不能声称线上尖峰已经消失。
- 本地原始证据：`tmp/allocator-tail-73772e6/` 中的 CI 日志、`udp-paired-runs.log`、`udp-medians.json`、`udp-candidate-perf.log`、`idle-paired-runs.log`、`same-pipeline-control.log`。
- 定位脚本：`tmp/unwind-musl-lock.py`；受限远端诊断目录：`/opt/cnode/profiles/allocator-tail-study/`。
- perf 符号化使用 `eu-unstrip` 重建 ELF，通过镜像绝对路径的 `--symfs` 解析用户态，并显式指定 `--kallsyms`。仅使用 build-id cache 曾出现地址偏移错误，其早期报告不作为用户态归因依据。
